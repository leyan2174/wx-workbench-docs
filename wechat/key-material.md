# 密钥材料的作用与生命周期

证据：C/U。来源：`src/scanner/{mod.rs,windows/account.rs}`、`src/daemon/{operations/init.rs,worker_keys.rs}`、`src/service/worker_keys.rs`及各媒体章节纯算法文件。hook细节沿用前轮来源说明，未在本轮重新审计全部指令定位。可独立实现程度：已给定材料的用途和数据库派生完整；自动捕获的指令定位与跨版本内存布局部分覆盖。

| 材料 | 当前作用 | 不应混淆为 |
|---|---|---|
| 捕获的32字节候选R | 与数据库盐做256000次PBKDF2，逐库验证 | 已证明的账号全部媒体根密钥 |
| 数据库K（32字节） | AES-256-CBC页恢复，派生页认证KH | 需要再次做256000次派生的密码 |
| 数据库S（16字节） | 原主库首页的派生盐 | WAL代次salt或秘密密码 |
| 图片AES（16字节）与XOR（1字节） | DAT V2分段恢复 | 数据库K的截断值 |
| V1固定ASCII材料 | DAT V1的AES段 | 用户账号秘密 |
| 表情16字节材料 | AES-128-CBC，当前IV=key | DAT ECB材料 |
| SNS字符串材料 | WxIsaac64模块的生成输入 | 通用AES key |
| 语音 | 未发现独立语音加密材料证据 | 把SILK编解码参数称为语音密钥 |

## 已证实的获取链

账号捕获实现通过Frida hook识别SHA-512常量及其指令引用，进而定位HMAC调用的候选32字节材料和ipad布局。候选以二进制通道回传，不写日志。用目标库首页盐派生K，并通过首页HMAC筛选；对收集到的目标数据库逐库验证，满足覆盖后才保存。抓到32字节数据不等于抓到正确密钥，必须有验证闭环。

源码还保留只读进程内存扫描路径，按版本选择原始材料或Config.Cipher相关路径。版本判断仅决定搜索策略；没有验证成功不能发布材料。本章未给出稳定的指令偏移或完整扫描器，因此捕获能力标记为部分覆盖，不建议照抄某版本地址。

普通查询只消费已有材料，不应隐式重启微信。重启捕获与只读扫描是不同授权动作。图片材料由独立提取与样本验证流程管理，不能在DAT解码失败时静默扫描另一账号。

## 当前初始化选择（2026-09-17复核）

| provider | 行为与边界 |
|---|---|
| saved（默认） | 只复用统一Store中已验证账号材料，再逐库验证；缺失或未验证即失败，不回退扫描 |
| memory | 显式授权的只读进程内存扫描 |
| account | 显式force与restart授权后捕获，可能需要用户确认登录 |

旧auto已删除并拒绝，不是saved的别名。已绑定运行上下文时，通过broker交付初始化材料并提交更新；account的Account和Databases在同一次revision更新提交。首次初始化或配置修复无正式绑定上下文时，init.rs直接创建/更新Store，只允许memory/account，saved拒绝。不能称全部初始化已经broker化。

## 项目的存储与使用

当前项目将账号、数据库和图片材料保存到版本化Windows当前用户DPAPI存储，记录绑定账号及身份锚点；更新一种材料时保留其他类型。磁盘临时文件只放受保护密文。读取后由固定账号的运行上下文传入业务适配器；纯解码器只接受明确材料。

这描述的是wx-workbench的管理策略，不是微信自身存储策略。DPAPI可用性受用户和机器上下文影响，不能保证复制文件即可跨设备恢复。材料失效应报验证失败，不能自动覆盖为另一个账号的数据。

受监督worker通过绑定账号、父进程、活跃子进程及权限的访问载体取得材料；更新携带expected revision，由daemon原子存储并处理幂等。bootstrap例外见上文；外部替换Store文件不承诺自动热重载。这是源码边界说明，不是本轮进程运行验证结论。

建议生命周期：显式获得→验证→受保护存储→按需解封→限定快照使用→销毁临时副本。日志只记录类型、阶段和成功/失败，不记录值；避免Debug输出、命令行参数或导出清单泄露。内存擦除是减小残留，不是对交换文件、崩溃转储或所有副本的绝对保证。

## 尚未证实

没有证据证明这些材料是否由服务器保存、跨设备是否一致、退出登录或重装是否改变、图片与数据库是否由同一根派生、SNS字符串与账号密钥是否有关。相同用户目录和相同材料长度都不是派生关系证据。

验证需要在获授权的隔离测试账号和固定版本上，仅记录材料等同性结果及验证通过的数据库/媒体范围，比较登录、退出、重启、迁移和升级前后变化；不公开原始材料。任何结论须注明样本数与条件，不能从单机一次观察扩展到整个微信平台。

## 当前宿主图片材料导入

`wx keys import-image --stdin`仅是项目宿主操作，不是微信已证实的密钥生成机制。标准输入为最多4096字节的严格JSON：`aes_key`是32个十六进制字符，`xor_key`为0至255；拒绝交互终端、命令行明文秘密和额外授权字段。`--sample-root`可指定离线样本，省略时使用选中账号附件目录；`--no-save`只验证，超时和读取预算必须生效。

CLI读取daemon的runtime、配置指纹与revision元数据，不读取旧秘密。输入只在内存中封装为DPAPI密文；worker验证固定来源上的V2样本，提交时预期revision必须同时匹配授权及实际Store版本。旧封装不能覆盖新更新，结果不明时不自动获取新revision重新封装重试；取消不撤销已提交事务。样本验证不证明其微信账号归属，DPAPI也不隔离同用户进程。

普通图片操作必须有选定Runtime及受保护快照，不接受明文AES覆盖；离线SNS不接受 `image_key_file`。有效快照无AES时仍可处理不依赖AES材料的格式，XOR格式字节与视频 `key_file` 保留各自语义。最终发布还需核对宿主材料revision；跨对象的验证与文件提交不是原子事务。
