# 验证方法与未知项

本仓只提供合成检查，没有真实账号夹具。封包检查、密码学原语检查、与上游差分、真实微信实验是不同证据，不应合并为一个“全部测试通过”。

2026-09-17源码对齐不继承此前生产测试结论。本文脚本只验证文档例子和描述的局部规则，即使再次通过，也不证明当前broker、初始化进程或全部微信机制的生产实现已通过测试。

## 可执行检查

在本仓根运行：

```powershell
python tools/check_docs.py
pwsh -NoProfile -File tools/check_crypto.ps1
python tools/check_wal.py
```

前者只需Python标准库，验证文档相对链接、围栏、部分私人标识模式，以及MD5命名、XOR例子、DAT分段、SNS包装反转顺序、SILK封包及错误、XML路径、媒体关联与歧义。它不运行SILK解码器或WxIsaac64。

后者需要PowerShell 7及其.NET运行时，验证AES-128原语已知向量、DAT完整填充块、表情CBC的IV=key，以及人工构造的4096字节数据库首页、PBKDF2派生、HMAC、CBC恢复和篡改拒绝。所有输入都是脚本里的固定人工序列，不含真实材料；不把自加密后解密的往返当作对微信真实格式的独立确认。

第三条使用Python标准库，执行15项WAL结构、HMAC和应用顺序检查。5组固定向量的生成参数和摘要见[wal-vectors.json](../evidence/wal-vectors.json)，可用`python tools/check_wal.py --write-vectors evidence/wal-vectors.json`重生成。它使用人工密文形状载荷，应用阶段用页面标签验证截断与覆盖；不执行AES或生产Rust代码，不能声称WAL端到端通过。

## 推荐回归矩阵

| 范围 | 正向 | 负向/边界 |
|---|---|---|
| 数据库 | 多页、不同盐、全部认证 | 错key、变IV、变页号、截断、处理中源变更 |
| WAL | 多提交、同页覆盖、收缩再增长 | 无提交、旧代次、坏帧后伪提交、认证失败 |
| DAT | P在15/16/17边界、raw为空、XOR为空 | 段重叠、溢出、坏padding、正确头错误尾 |
| 表情 | 已给定材料的CBC恢复 | 非整块、短key、字节内空白、宽松padding差别 |
| SNS | 包装长度1/7/8/9、128KiB后缀不变 | 无引擎、未知资产、空key、预算耗尽 |
| 语音 | 正常帧、可选02、补结束标记 | 半个长度、载荷截断、FF FF位于载荷内部、歧义媒体 |
| 导出 | 跨分片同秒、重复运行 | 缺分片、损坏XML、并发目标修改、部分媒体失败 |

其中WAL结构/认证/应用顺序已有上述检查；WAL与AES端到端、多页主库和完整媒体回归仍是推荐补充，不能仅因表格列出就说本仓已执行。实际运行结果以[状态](../STATUS.md)为准。

## 未知项的实验设计

- **跨设备材料一致性**：在授权测试账号同一版本的两台设备上，各自验证材料可用后，仅比较等同性与对应数据库范围。记录是否迁移、是否重新登录，不公开材料。
- **退出/重装生命周期**：固定版本，分别在重启、退出重登、迁移后验证旧材料能否恢复新旧数据库及媒体；区分盐变化与候选变化。
- **共同根派生**：只有提出具体可检验公式并跨独立样本验证，才能报告派生关系；账号相同、长度相同或一起出现都不足够。
- **服务器保存**：当前本地源码无此证据；需要官方协议/文档或具备合法权限的独立协议证据。本地扫描结果无法回答。
- **SNS内部算法**：先确认可用规范/源码的权利，再核对初始化、字序、计数及完整向量；不能因类名WxIsaac64就用任意ISAAC库替代。
- **packed_info**：构造不同附件类型、多内容标识和未知字段，验证完整结构解码；当前首个32字符提取仍存在启发式局限。
- **通话与语音**：分别验证通话摘要本地化、群通话类型、SILK编码输入；不推定存在独立语音密钥或通话录音。

所有新增实验记录必须包含微信版本、系统、输入生成方法、预期、结果、失败和范围。不得把私人日志原样作为公开证据。
